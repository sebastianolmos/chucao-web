  - **Objective:** Create the trusted persistence boundary and constraints needed by the round lifecycle.
  - **Depends on:** None; use the existing VS-01/VS-02 migrations as prerequisites.
  - **References:** FR-01, FR-07, FR-08; NFR-04–NFR-06; AC-01, AC-07, AC-10; plan sections 4 and 7; CHECK-02, CHECK-04.
  - **Work:** Add a versioned VS-03 migration for rounds, appearances, and `round_operations`. Enforce one current round per list, positive unique appearance order per round, allowed appearance origins, and the owner chain through the parent list. Enable/force RLS, revoke direct writes, and grant only the required authenticated RPC execution. Keep active rounds attached to lists; allow closed rounds to be detached for the accepted future anonymization. Include fields that allow an anonymized round to retain only an appearance total, with exact timestamps and user/list/concept links removable. Do not implement list deletion. Update `src/lib/database.types.ts` to match the schema contract.
  - **Verification:** Run `npx supabase db reset --local` and `npx supabase db lint --local`. Review table constraints, indexes, grants, RLS policies, and the detachable closed-round shape against Q-04. Use synthetic data only.

- [x] **T02 — Implement ordered, idempotent round operations**
  - **Objective:** Persist first-round creation, manual mark, draw, return-to-pending, and new-round transitions atomically under the accepted per-list ordering rule.
  - **Depends on:** T01.
  - **References:** FR-01, FR-03–FR-08; NFR-01, NFR-04–NFR-06; AC-01–AC-07, AC-09–AC-10; plan sections 4–6; CHECK-02–CHECK-04, CHECK-06.
  - **Work:** Add fixed-search-path security-definer RPCs for ensuring the current round, marking seen, drawing, returning to pending, and starting a new round. For every action, derive identity from `auth.uid()`, verify ownership, lock the parent list, then check/record the client operation UUID and apply the action in one transaction. Return the stored result for a repeated UUID. Select uniformly from the current pending set; record an immutable appearance with origin and position for mark/draw only. Reset active concepts to pending on confirmed new round. Update the existing concept edit/delete RPCs to take the same parent-list lock before concept mutation; deletion must replace the displayable historical title snapshot with the deletion marker in the same transaction. Do not include titles in operation records or errors.
  - **Verification:** With synthetic owner A, exercise empty/first round, mark, draw/exhaustion, return, cancel/no-write and confirm-new-round, duplicate operation UUID, pre-commit failure, and a simulated lost response followed by retrying the same UUID. Use two local sessions for distinct concurrent draws and competing marks. Confirm unique order, one effect per intent, no partial writes, and correct tombstone redaction.
  - **Done when:** Every operation is transactionally consistent and ordered for one list; same-intent retry returns the recorded result; distinct actions use current state; rejected operations add no unintended appearance; deleted titles are absent from historical display fields; migration/RPC checks pass locally.
